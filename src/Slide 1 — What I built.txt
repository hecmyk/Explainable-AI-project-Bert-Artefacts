Slide 1 — What I built

Title: LLM Agent for Rule Catalog & Definition Management

Subtitle: Human-in-the-loop, built on top of the team's rule engine

Bullets:

Covers Ticket 1 objectives 3 & 4: optimize existing rules, discover new ones
Plus: drafts business definitions for undocumented columns
All agent outputs go through a human review queue before activation

Speaker note (~30 sec):
"On top of the deterministic rule engine my teammates built, I added an interactive LLM agent that helps a data quality owner improve the catalog. It handles three tasks: finding redundant or dead rules, proposing new rules for uncovered columns, and drafting definitions for columns that don't yet have one. Nothing is applied automatically — every agent output waits for a human decision."

Slide 2 — Architecture

Title: Architecture

Visual — simple horizontal flow:

User (chat)
   ↓
Agent  ──  gpt-oss-120b-ITG  (ReAct loop, LangGraph)
   ↓
9 Tools (Python, deterministic)
   ├─ Read: list_rules, list_uncovered_columns,
   │        list_columns_without_definition, profile_column,
   │        get_failures
   └─ Write: propose_add_rule, propose_modify_rule,
            propose_delete_rule, propose_definition
   ↓
proposals.json  (pending queue)
   ↓
Streamlit review UI  →  Approve / Reject

Key design points (2 bullets on slide):

LLM chooses which tools to call — all business logic stays in deterministic Python
Write tools never touch rules.json directly; they append to a pending queue

Speaker note (~1 min):
"The user chats with the agent in a Streamlit tab. Under the hood it's a ReAct loop built with LangGraph. The agent has access to nine tools, split into read tools that expose the current state — the rule catalog, the data profile, the coverage matrix — and write tools that create proposals. The write tools never mutate the rule catalog directly; they append to a pending queue. That queue is the single control point where the human decides what actually happens. This satisfies the governance requirement in the ticket: no AI-proposed change is activated without a logged human approval."

→ [switch to Agent Proposals tab]

"Each proposition carries a rationale grounded in what the agent observed — here it flagged two dead rules and one duplicate. I approve or reject."

"The approval is logged. Applying approved proposals back to rules.json is the next iteration — kept out of this POC to stay within the guardrail scope."
